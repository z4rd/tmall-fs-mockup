## 已知陷阱

- 超大 frame 无法单张渲染，部分节点 `get_screenshot` 稳定超时 → 退回 `get_metadata` / `get_design_context` 读结构，或逐个查子节点。
- **`get_metadata` 会漏报子层级。** `4021:22726`、`4040:24332` 用 `get_metadata` 返回空 frame，用 `get_design_context` 却能读出 2 个 / 6 个子节点。**凡遇空 frame 必须用 `get_design_context` 二次确认。**
- `get_design_context` 若返回 Code Connect 提示，带 `disableCodeConnect: false` 重试。
- **图层名一律不可信**，页面归属只按用户给定的映射判断。已发现：两张宝贝页同名 `Nike FS - Women - NSW`；男装稿命名为 `Nike FS - Women - D11`；Sports Zone 主题稿用设计系统遗留名（`Running — 74` / `B-BALL`）与实际 tab 无关。
- **`Group` 节点的子级坐标是透传的**（与父节点同一坐标空间），`Frame` 的才是相对坐标。读 ACG 首页 `2553:71386` 时会撞上这一点。
- ~~通用二级产品墙每个店铺一套节点，说明它按店铺主题参数化~~ → **实测结论**：四张是四张互不相同的**静态位图**，不是参数化模板。`ProductWallProps.store` 是切图选择键，见 §2.8。
